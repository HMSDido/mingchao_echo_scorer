# 鸣潮声骸评分（mingchao_echo_scorer）

一款**完全离线**的《鸣潮》声骸评分工具，支持 **Android** 与 **Windows**。
录入 5 件声骸的副词条档位，按你为角色设定的 13 项系数权重实时算出评分与评级，
并附带预期最高分、目标分达成概率等辅助功能。

不联网、不登录、无广告、无统计上报，所有数据以 JSON 形式保存在本地。

- 版本：`1.0.3+4`
- 技术栈：Flutter 3.47 / Dart 3.13
- 仓库：<https://github.com/HMSDido/mingchao_echo_scorer>

## 下载

安装包发布在 **[Releases](https://github.com/HMSDido/mingchao_echo_scorer/releases)** 页面，

想一并清掉就手动删除该目录，想保留或换机迁移就先备份它。

## 一、简介

《鸣潮》的声骸有 13 种副词条属性，每种属性可以开到不同的档位，
一个声骸最多开出 5 条副词条。判断一件声骸「好不好」，本质上取决于你在练哪个角色、
看重哪些属性。

本应用把这个判断过程量化：

1. 你为角色写一份**系数配置**——13 项副词条各自的权重（不重要的属性填 0）。
2. 录入声骸实际开出的属性与档位。
3. 应用按 `档位数值 × 系数` 求和得到评分，并与该角色下的**理论最高分**比较得出评级。

同一件声骸在不同角色手里价值完全不同，所以评分不是绝对的「好 / 坏」，
而是**相对于你所练角色的契合度**。

## 三、基础使用方法

### 1. 建立角色系数配置

进入左侧「**编辑角色系数**」→「**新建配置**」，命名后逐项填入 13 个副词条的系数。
不需要的属性留 0 即可。配置可随时编辑，也可以粘贴别人分享的链接导入（见[第四节](#四社区贡献)）。

> 系数建议按「这条属性对该角色的相对价值」来定，例如主 C 通常给暴击率 / 暴击伤害
> 较高权重，辅助则更看重共鸣效率。数值大小本身不影响评级——评级看的是
> 实际分与理论最高分的比值，所以整体缩放系数不改变结果，**相对比例才是关键**。

### 2. 新建评分文件并选择角色

在左侧「**评分文件**」面板点「**新建文件**」并命名（命名建议带链数，如「01长离」「21守岸人」），
然后在总览页点「**选择角色**」，从配置列表里挑一份。选定后系数会作为**快照**写入该文件，
之后修改配置不会影响已保存的文件。随时可点总分下方角色名旁的「**更换系数**」换一份快照，
换完即为内容改动，关闭文件时会按脏检查提示保存。

### 3. 录入声骸档位

点任意一张声骸卡片进入详情页，13 行副词条逐行选择档位：
`0` 表示未开出，`1–8` 为具体档位（固定攻击、固定防御只有 1–4 档）。
档位数值可在[资料数据](#八资料数据内置)中查到。

### 4. 查看输出

详情页右侧依次给出三块结果：

- **① 当前评分** —— 分数、评级、已开词条数；
- **② 预期最高分** —— 剩余槽位全开最优时的上限，并列出「还差哪几条」；
- **③ 目标分数与达成概率** —— 填入目标分后显示达标概率。

总览页同时汇总 5 件声骸的分数、总分与总评级，并输出**副词条合计**
（5 件声骸各属性档位数值之和）；还可以选填**暴击阈值**，
超出阈值的暴击率合计不计入总分（见[第六节](#六计算公式)）。

### 5. 保存与分享

详情页「**保存本声骸**」写入当前声骸；文件的 `⋮` 菜单（宽屏在文件栏、窄屏在顶栏）
提供保存、重命名、复制分享链接、关闭文件、删除文件；评分文件列表的 `⋮` 里还有
「**复制全部分享链接**」——把已打开的文件一行一条编码复制，对方可以整批导入；
以及「**批量删除**」——勾选多个文件一次删掉，连同各自的文件夹从磁盘上移除。
关闭或切换文件时，只有**内容真的变了**才会提示保存。

「**粘贴导入**」读剪贴板文本，可同时接收评分文件与角色系数配置：
粘错了类型不会静默生成一条垃圾数据，而是明确提示该去哪儿导入。
多份内容一行一条，坏行只会被跳过并列出原因，不影响同一批的其他条目。

### 6. 分组管理

配置列表和评分文件列表都可以自建分组（中间层），用来按角色归类（如「绯雪」「忌炎」）。

- **新建**：文件栏/配置页的 `⋮`（宽屏文件栏还有专门的图标）→「新建分组」；
- **移动**：按住行首把手把条目拖到组头下方即入组，Windows 直接拖、Android 长按后拖；
  拖组头会带走整组，组与组、组与根层之间任意排序；
- **组内新建**：组菜单里可直接在该组下新建配置/文件；
- **删除分组**：只删分组标题本身，组内条目释放回列表根部，**不会删任何数据**；
- **清空分组**：连同组内全部条目一起删除（有二次确认，不可撤销）。

分组与排序属于**本机界面偏好**，存在应用设置里——不写进评分 JSON，
也不进分享链接，导入导出与其他用户完全无关。

## 四、社区贡献

本应用完全离线，**不会自动下载任何配置**。仓库里的
[`共享角色系数配置文件/`](共享角色系数配置文件/)
目录只存放社区整理好的现成角色系数配置——**中间一层按角色名分文件夹**
（如 `绯雪/`、`守岸人/`），同一角色的不同链数配置放在同一个角色文件夹里，
一个配置就是一个 `.txt` 文件，文件里就是应用「复制分享链接」产出的那一整行
`echoscorer://…`，复制即可用。

### 4.1 取用现成的配置

1. 打开上面的目录，进入角色名文件夹，点需要的 `.txt` 文件。GitHub 页面会直接显示那一行
   `echoscorer://…`，**选中整行复制**即可；
   也可以 `Download raw file` 后用文本编辑器打开复制（下载由你自己的浏览器完成，应用不参与）。
2. 打开应用，进入「**编辑角色系数**」页 → 点右上角 `⋮` →「**从剪贴板导入配置**」。
   一次也可以粘多条（一行一条）。
3. 导入后配置会复制一份到本地。此后你再改动这份文本，
   **不会**影响已经保存的评分文件——评分文件在选定角色时就把系数作为快照代入了公式。

应用内「编辑角色系数」页顶部的横幅也提供了直达该目录的入口，点击后由系统浏览器打开。

> 目录当前收录：`绯雪/` 下 01 / 11 / 21 / 31 / 41 / 51 / 61 / 65 共 8 档链数配置。
> 此后每份通过审阅的配置都会直接出现在对应角色文件夹里，
> 这个目录**只放配置文件**，说明文字一律写在本 README 与 [docs/DATA.md](docs/DATA.md)。

### 4.2 文件命名规范

文件名标注 **角色链数 + 专武链 + 角色名 + 系数**，前两位数字分别是声骸链数和专武链数：

| 文件名 | 含义 |
| --- | --- |
| `31绯雪系数.txt` | 声骸 3 链、专武 1 链的绯雪 |
| `00绯雪系数.txt` | 0 链角色、无专武的绯雪 |
| `41守岸人系数.txt` | 声骸 4 链、专武 1 链的守岸人 |

链数不同请作为独立文件提交，不要覆盖同名配置；同一角色（如 `00绯雪系数`、`31绯雪系数`、`61绯雪系数`）
统一放进以角色名命名的中间层文件夹（如 `共享角色系数配置文件/绯雪/`）。

> 在应用里新建或重命名配置时就按上面的规范写好名字，
> 复制出来的分享链接会带上这个名字，收录时直接沿用。

### 4.3 文件格式

目录里的 `.txt` 只有一行 `echoscorer://` + Base64（UTF-8 JSON），
和应用里 `⋮` →「复制分享链接」得到的文本是同一种东西，
所以中文和引号不会在网页、聊天软件里被转义坏掉。
以 [`绯雪/31绯雪系数.txt`](共享角色系数配置文件/绯雪/31绯雪系数.txt) 为例，文件内容就是：

```
echoscorer://eyJmb3JtYXQiOjEsImlkIjoiaG1zem93MHN3YS0xNDEyZndzIiwibmFtZSI6IjMx57uv6ZuqIiwiY29lZmZpY2llbnRzIjp7ImNyaXRSYXRlIjoyLjE1LCJjcml0RG1nIjoxLjAsImF0a1BjdCI6MC44NiwibGliZXJhdGlvbkJvbnVzIjowLjk3NywiZmxhdEF0ayI6MC4wODJ9LCJjcmVhdGVkQXQiOiIyMDI2LTEwLTAxVDExOjUyOjUwLjI3NjkzOFoiLCJ1cGRhdGVkQXQiOiIyMDI2LTEwLTAxVDEyOjU5OjM0LjExMDIwMloifQ==
```

把 Base64 解回来（应用导入时做的就是这一步）得到这段 JSON：

```json
{
  "format": 1,
  "id": "hmszow0swa-1412fws",
  "name": "31绯雪",
  "coefficients": {
    "critRate": 2.15,
    "critDmg": 1.0,
    "atkPct": 0.86,
    "liberationBonus": 0.977,
    "flatAtk": 0.082
  },
  "createdAt": "2026-10-01T11:52:50.276938Z",
  "updatedAt": "2026-10-01T12:59:34.110202Z"
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `format` | 整数 | 格式版本，当前为 `1` |
| `id` | 字符串 | 配置标识，只允许字母、数字、`-`、`_`；导入时若冲突会自动重新生成 |
| `name` | 字符串 | 配置显示名称，建议与文件名中的角色名一致 |
| `coefficients` | 对象 | 13 项副词条权重，**系数为 0 的项可省略**，读取时按 0 补齐 |
| `createdAt` / `updatedAt` | 字符串 | ISO 8601（UTC）时间戳 |

`coefficients` 的合法键名共 13 个（未知键忽略、负值按 0 处理、最多 3 位小数）：
`critRate` 暴击率 · `critDmg` 暴击伤害 · `atkPct` 攻击% · `hpPct` 生命% · `defPct` 防御% ·
`basicAtkBonus` 普攻伤害加成 · `heavyAtkBonus` 重击伤害加成 · `skillBonus` 共鸣技能伤害加成 ·
`liberationBonus` 共鸣解放伤害加成 · `energyRegen` 共鸣效率 · `flatAtk` 固定攻击 ·
`flatHp` 固定生命 · `flatDef` 固定防御

这份配置只写了 5 项，其余 8 项在导入时自动补 0。

完整字段与容错规则见 [docs/DATA.md](docs/DATA.md)。

## 五、额外玩法

### 5.1 目标分达成概率

在详情页填入一个目标分数，应用会算出「剩下没开的词条随机强化后，
这件声骸最终能达到该分数」的概率。

模型是精确计算而非模拟：已录入 i 条后，剩余 (5 − i) 条词条的**属性本身也是随机的**
——从 (13 − i) 个未选中的属性里等概率不放回抽取，每个被抽中的属性再按自身档位分布
独立摇档。实现上用整数化 DP + 分组折叠 + 上下界剪枝，把 C(13,5) × 8⁵ ≈ 4200 万种
组合压到毫秒级，结果无浮点累积误差。

用途：判断「这件半成品还值不值得继续投入」，或者反过来定一个自己愿意接受的目标分，
看当前进度离它有多远。

### 5.2 预期最高分

已录入 i 条词条时，在剩下的 (13 − i) 个未选属性中取 `系数 × 最高档位数值`
最大的 (5 − i) 项（不放回、互异），加上当前分数即为**预期最高分**——
这是「后续全开最优」的上限，界面同时列出应该开哪几条属性。

与理论最高分的区别：理论最高分是全新声骸的满分基准（评级分母），
预期最高分是**这一件**在当前进度下的现实上限。

### 5.3 自定义背景图

在「系统设置」里选择一张本地图片作为应用背景，图片会被复制到应用的数据目录，
随时可清除恢复默认纯色背景。不联网下载任何图片。

### 5.4 系数快照与多角色对照

因为每份评分文件都保存了自己的系数快照，你可以：

- 为同一角色建多套配置（如「31绯雪系数」与「00绯雪系数」），分别建文件对比链数差异带来的评分变化；
- 保留旧版本权重下的历史评分，之后调整配置也不会追溯改写；
- 用「复制分享链接」把配置发给别人，对方粘贴导入后得到的分数与你完全一致。

## 六、计算公式

### 单件声骸评分

```
评分 = Σ ( 档位数值 × 该项系数 )      // 遍历 13 项副词条，档位 0 的项不参与
```

- **档位数值**取自内置档位表，百分比属性去掉 `%`（`7.5%` 记作 `7.5`），
  **不是**档位序号；
- 各项以全精度累加，**最后**统一四舍五入到 2 位小数显示；
- 系数最多 3 位小数。

### 总分与暴击阈值

```
总分 = Σ 5 件声骸当前评分 − 暴击率超出量 × 暴击率系数
```

- 默认**不设阈值**，总分就是 5 件声骸当前评分之和；
- 在总览页填入**暴击阈值**（`XX.X%`）后，5 件声骸的暴击率合计超过该值时，
  超出部分不再计入总分，总览页同时给出提醒；
- 阈值**只作用于总分**：单件声骸的当前评分与评级不受影响；
- 总览页还输出**副词条合计**：5 件声骸各属性档位数值之和；
  超过 5 条词条的声骸不计入合计与总分。

### 理论最高分

```
单件理论最高分 = Σ top5 ( 系数 × 该属性最高档位数值 )
总理论最高分   = 5 × 单件理论最高分
```

即从 13 项中挑出「系数 × 满档数值」最大的 5 项相加，对应一件完美声骸的满分。

### 评级比值

```
比值 = 显示分 ÷ 理论最高分
```

比值使用**已取整的显示分**，保证界面上的分数与评级自洽；
理论最高分为 0（系数全 0）时不给评级。

### 超过 5 条副词条

一件声骸最多 5 条非 0 档位。若录入超过 5 条（例如手误或数据异常），
应用**不输出分数与评级**，并在界面上给出提示。

## 七、评级标准

| 评级 | 比值区间 |
| --- | --- |
| **ACE** | ≥ 80% |
| **S** | 70% – 80% |
| **A** | 60% – 70% |
| **B** | 50% – 60% |
| **C** | 40% – 50% |
| **—**（无评级） | < 40%，或理论最高分为 0 |

- 恰好命中阈值时取**较高**一档（比值 80.00% 即 ACE）；
- 比值超过 100% 仍为 ACE；
- 总评级按五件合计分与总理论最高分的比值计算，规则相同。

## 八、资料数据（内置）

13 种副词条属性、各档位数值、4 组档位概率分布、评级阈值与 JSON 文件格式，

## 九、数据存储与隐私

默认存储位置：

| 平台 | 路径 |
| --- | --- |
| Windows | `文档\mingchao_echo_scorer` |
| Android | `Android/data/io.github.hmsdido.mingchao_echo_scorer/files/mingchao_echo_scorer` |

目录结构：

```
mingchao_echo_scorer/
├── profiles/          # 角色系数配置，每份一个 <id>.json
└── scores/            # 评分文件，每份一个 <文件名>/score.json
    └── 绯雪/score.json
```

自定义背景图另存于应用私有支持目录下的 `background/`，不占用上面的数据目录。

- 可在「文件存储位置」里把根目录改到任意本地文件夹；
- 全部是明文 JSON，可以直接用文本编辑器查看、备份、迁移；
- 写入采用「临时文件 + 原子重命名」，中断不会产生半截文件；
- **不收集任何数据**：无账号、无网络权限、无遥测、无崩溃上报。
  唯一的外部跳转是用系统浏览器打开本仓库页面。

## 十、技术栈与项目结构

- Flutter 3.47.5 stable / Dart 3.13.4，Material 3，`zh_CN` 本地化；
- 状态管理：`provider` + `ChangeNotifier`；
- 存储：`path_provider` + `shared_preferences` + 明文 JSON；
- 选择文件夹与背景图：`file_picker`（导入导出走剪贴板分享链接，不用文件对话框）；
- Windows 关闭拦截：`window_manager`；
- 外部链接：`url_launcher`。

分层架构，依赖只向下流动（`ui → state → domain/data → core`）：

```
lib/
├── core/        # 常量、格式化、主题、本地文件读写
├── data/
│   ├── catalog/       # 内置副词条档位表与概率表
│   ├── models/        # ScoreFile / EchoEntry / Coefficients / CoefficientProfile / Rating
│   └── repositories/  # StorageService / ScoreRepository / ProfileRepository / SettingsRepository
├── domain/      # 纯计算：评分、预期最高分、达成概率（不依赖 Flutter 与 IO）
├── state/       # ChangeNotifier 控制器
└── ui/          # shell / overview / detail / profiles / settings / actions / widgets
```

派生数据（分数、评级、预期最高分、概率）**一律不落盘**，每次由档位与系数重新计算。

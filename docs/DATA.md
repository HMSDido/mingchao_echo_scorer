# 资料数据

本文件汇总《鸣潮声骸评分》内置的全部数据表。**这些数据全部编译进应用**
（`lib/data/catalog/`），不通过任何方式下载，因此应用可以完全离线运行。

- 13 种副词条属性与各档位数值
- 4 组档位概率分布
- 评级阈值
- 配置文件 JSON 格式

## 二、档位概率分布

概率一律以「整数分子 / 组内公分母」表示，避免十进制截断误差进入计算。
表中百分比为四舍五入到 2 位的显示值，实际计算使用分数。

## 三、评级阈值

评级比值 = 显示分 ÷ 理论最高分。恰好命中阈值时取较高一档；
比值超过 100% 仍为 ACE；理论最高分为 0（系数全 0）时无评级。

| 评级 | 比值下限 |
| --- | --- |
| ACE | ≥ 80% |
| S | ≥ 70% |
| A | ≥ 60% |
| B | ≥ 50% |
| C | ≥ 40% |
| —（无评级） | < 40% |

## 四、配置文件 JSON 格式

格式版本 `format` 当前为 `1`。

### 角色系数配置（`profiles/<id>.json`）

```json
{
  "format": 1,
  "id": "hmszow0swa-1412fws",
  "name": "31绯雪",
  "coefficients": {
    "critRate": 2.15,
    "critDmg": 1.0,
    "atkPct": 0.86,
    "liberationBonus": 0.977,
    "flatAtk": 0.082
  },
  "createdAt": "2026-10-01T11:52:50.276938Z",
  "updatedAt": "2026-10-01T12:59:34.110202Z"
}
```

上例即仓库 `共享角色系数配置文件/31绯雪系数.txt` 里那行 `echoscorer://…`
Base64 解码后的实际内容，只写了 5 项非 0 系数。仓库目录存放的是分享链接文本
（应用「复制分享链接」的产物），应用导入时先解码回这样的 JSON 再按本节规则读取。

- `id` 只允许字母、数字、`-`、`_`（防止路径穿越）；导入时若冲突会自动重新生成。
- `coefficients` 只写非 0 项，缺失的键读取时按 0 补齐，未知键忽略，负值按 0 处理，
  数值最多保留 3 位小数。

### 评分文件（`scores/<文件夹名>/score.json`）

```json
{
  "format": 1,
  "id": "a1b2c3d4",
  "name": "绯雪",
  "profile": { "id": "preset-31-feixue", "name": "31绯雪系数" },
  "coefficients": { "critRate": 1.0, "critDmg": 1.2 },
  "echoes": [
    {
      "slot": 0,
      "name": "声骸1",
      "tiers": { "critRate": 3, "critDmg": 5 },
      "targetScore": 80.0
    }
  ],
  "critThreshold": 25.0,
  "updatedAt": "2026-10-01T08:00:00.000Z"
}
```

- `echoes` 恒为 5 个槽位（`slot` 0–4），缺失或重复的槽位在读取时按默认值归位。
- `tiers` 的值是**档位序号**（1–8，固定攻击 / 防御为 1–4）；档位 0（未开出）不写入文件。
- `targetScore` 是**每件声骸各自的**目标分，未设置时不写该键、也不计算达成概率。
- `critThreshold` 是选填的**暴击率阈值**（百分比数值，如 `25.0` 即 25.0%），
  未设置时不写该键；设置后 5 件声骸的暴击率合计超出该值的部分不计入总分。
- `coefficients` 是选定角色时的**系数快照**，之后修改配置不会追溯改动本文件；
  需要跟进新权重时由用户显式「重新套用配置」。
- 分数、评级、预期最高分、达成概率**都不落盘**，每次打开都由档位与系数重新计算。
